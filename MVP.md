# MVP Spec: Proactive Training Agent (HackUTA)

> Context for teammates + their coding agents. Read fully before building.

## 0. Product in one line

An agent that watches your ML training runs, texts you the moment one breaks, calls you on FaceTime when it's serious, **shows you your laptop screen live on the call**, explains what went wrong out loud, and fixes it on your OK.

**One agent, two bodies:**
- **Desktop** (the hands): runs on your laptop next to your repo. Watches the run, reads logs/code, applies fixes, resumes.
- **Phone** (the eyes + voice): Chert iMessage + FaceTime. Notifies, explains, shows the screen, takes approval.

**Vertical:** ML engineers/students running long training jobs.
**Tracks:** Chert (FaceTime), ElevenLabs (voice), Gemini (reasoning), xAI/Grok (optional).

---

## 1. Key platform fact: Chert + LiveKit

Chert's "Place a call" supports **Agent = "Your own room (LiveKit or direct)"**, **Media transport = LiveKit**. Chert places the FaceTime call (to a phone number or Apple ID, from a provisioned Chert line) and **bridges it into a LiveKit room we control**.

Call parameters Chert needs:
- Destination (phone number / Apple ID), From (our Chert line)
- LiveKit URL (`wss://<project>.livekit.cloud`)
- Call-scoped participant token (short-lived, generated by us per call)
- Remote participant identity (name of the FaceTime caller inside our room)
- "Request video in addition to audio" → we also receive the caller's camera

Therefore:
- **Our agent runs as a LiveKit participant on the laptop.** We own STT → LLM → TTS.
- **Live screenshare = our agent publishes a screen video track** into the room; the FaceTime user sees it.
- Agent runs next to the repo, so it calls the fixer **locally**, no remote tool server needed.

## 2. Pipeline

```
 LAPTOP                                                       PHONE
 ──────                                                       ─────
 train.py ── stdout/stderr + metrics.jsonl
     ▼
 [1] WATCHER ── failure? (crash / NaN / OOM / plateau)
     ▼ yes
 [2] INCIDENT BUILDER  traceback + log tail + metrics + config + git diff
     ▼
 [3] TRIAGE (Gemini) → {summary, cause, fix, severity}
     │
     ├──► [4] NOTIFY: Chert iMessage API ───────────────► 📱 alert
     │         "NaN loss at step 4.2k. Likely LR too high.      reply FIX / CALL
     │          Reply FIX or CALL"                               │
     │                                                           │
     │   reply arrives via Chert webhook (small FastAPI + tunnel)│
     │                                                           │
     │   severity HIGH or reply CALL                             │
     ├──► [5] ESCALATE: create LiveKit room + tokens             │
     │        → Chert API places FaceTime call into that room ──► 📱 rings
     │                                                           │
     │   [6] LIVEKIT AGENT (in room, on laptop)                  │
     │        STT (user speech) → Gemini (reason + tools)        │
     │        → ElevenLabs TTS (voice)  ─────────────────────► 🔊
     │        publishes SCREEN TRACK (repo/logs/loss plot) ────► 🖥️ live
     │        receives caller CAMERA (optional)                  │
     │                                                           │
     │   user: "lower the LR and resume"                         │
     ▼                                                           │
 [7] FIXER (local tools)  git branch → patch → (dry run) → resume → verify
     ▼
 [4] NOTIFY: iMessage report + before/after screenshot ────────► 📱
```

## 3. Components

| # | Module | Responsibility | Tech |
|---|--------|----------------|------|
| 1 | Watcher | Launch/attach training subprocess; tail output; read metrics; run detectors | Python `subprocess` |
| 2 | Incident builder | Assemble `Incident` | Python, git |
| 3 | Triage | Structured diagnosis | Gemini API |
| 4 | Notify | Send iMessages; receive replies via webhook | Chert Messages API, FastAPI, ngrok/cloudflared |
| 5 | Escalate | Create LiveKit room, mint tokens, ask Chert to place call into it | `livekit-api`, Chert API |
| 6 | Call agent | Voice conversation + tool use + screen publishing | `livekit-agents` (Python) w/ Gemini LLM plugin, ElevenLabs TTS plugin, an STT plugin |
| 6b | Screen publisher | Capture screen (or render loss plot) → `rtc.VideoSource` → publish track | `mss` / matplotlib, `livekit.rtc` |
| 7 | Fixer | Apply fix on new branch, optional dry run, resume from checkpoint, verify | Python, git |

**Detectors:** `crash` (non-zero exit / traceback), `nan` (loss NaN/Inf), `oom` ("out of memory"), `plateau` (no improvement over N steps), `overfit` (stretch: val ↑ while train ↓).

**Call agent tools (local Python functions exposed to Gemini):**
`get_incident()`, `get_logs(n)`, `read_file(path)`, `show(view)` (switch screen track: `repo` | `logs` | `plot`), `apply_fix(changes)`, `dry_run()`, `resume()`, `get_status()`.

## 4. Data contracts

**Incident (Pydantic / JSON):**
```json
{
  "id": "inc_001",
  "run_id": "run_2026-11-14_1530",
  "type": "nan | crash | oom | plateau | overfit",
  "step": 4200,
  "detected_at": "ISO-8601",
  "traceback": "string | null",
  "log_tail": ["last 200 lines"],
  "metrics_tail": [{"step": 4190, "loss": 2.31, "val_loss": 2.40, "lr": 0.01}],
  "config": {"lr": 0.01, "batch_size": 64},
  "git_diff": "string",
  "triage": {
    "summary": "Loss went NaN at step 4200.",
    "cause": "Learning rate too high for this batch size.",
    "fix": {"kind": "config", "changes": {"lr": 0.0003}},
    "severity": "LOW | HIGH"
  },
  "status": "open | notified | calling | fixing | resolved"
}
```

**Metrics:** training appends one line per log step to `runs/<run_id>/metrics.jsonl`:
```json
{"step": 100, "loss": 2.91, "val_loss": null, "lr": 0.01, "time": 12.3}
```

**Severity (v1):** `crash` / `oom` / `nan` → HIGH (call). `plateau` / `overfit` → LOW (text only). Gemini may upgrade.

**Safety:** all code changes on branch `agent/fix-<incident_id>`; nothing destructive without explicit spoken/texted "yes"; every action logged to `runs/<run_id>/agent_log.jsonl`.

## 6. Setup checklist

1. **Provision a Chert FaceTime line** (Lines tab shows 0 — do this first).
2. Create **LiveKit Cloud** project → URL, API key, secret.
3. Get Gemini + ElevenLabs keys.
4. Tunnel (ngrok/cloudflared) for the Chert iMessage webhook only.
5. **Smoke test before anything else:** Chert calls your phone → joins our LiveKit room → agent says "hello" → publishes screen track → you see your laptop on FaceTime.

---

## 7. Build order

1. Smoke test (section 6.5).
2. `demo/train.py` + `bad_lr.yaml` reliably NaNs ~2 min in.
3. Watcher + detectors → Incident.
4. Gemini triage → JSON.
5. iMessage alert + reply webhook.
6. Escalation: auto-call into room on HIGH / CALL.
7. Call agent: explains incident (Gemini + ElevenLabs), shows screen, takes voice approval.
8. Fixer: apply → resume → verify → iMessage report.
9. Wow layers: dry run before fix, live loss-plot view, caller camera input (show whiteboard → code).

Each step demoable before the next. Keep `main` working.

## 9. Demo (60s)

1. Launch `bad_lr.yaml`, walk away.
2. ~2 min: loss → NaN. Judge's phone gets iMessage.
3. HIGH → judge's phone rings (FaceTime).
4. Agent (ElevenLabs voice) explains; **judge sees the laptop screen live** — logs, then the loss curve blowing up.
5. Judge: "do it." Agent fixes, resumes, shows loss recovering live, texts before/after report.
